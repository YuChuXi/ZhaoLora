# 筛选

瀑布流浏览与挑选样本；支持本地目录与 Gelbooru / Danbooru / e621 / Bilibili。

## 本地模式

1. 「来源」选 **本地**，右上角勾选工作目录。
2. 单击选中 / 取消；状态栏 **共 / 已选 / 回收站**（回收站计数仅在回收站视图下显示）。
3. **删除** 将选中项移入回收站；**恢复** 可整库或按选中恢复。
4. **元数据** 可重生成 Caption 或刷新在线来源元数据。
5. 右键可找色调相似图。

### 排序

顶栏「排序」支持名称 / 时间 / 美学 / 评分项 / 像素 / **搜索**。当前排序项对应的字段
置于卡片附加文本首位（名称排序时为文件名），其余字段按时间 / 美学 / 评分项 / 像素 /
名称的默认顺序排列。

- **评分项**：来自数据集在评分页定义的 WD14 概率评分项（如 CSAM / NSFW），按分值降序；
  卡片附加文本显示各评分项分值。无分值的图片置于末尾。

- **时间**：按在线来源发布时间（meta JSON 的 `posted_at`）新→旧排序；无发布时间的图片置于末尾按名称排序。

- **搜索**：基于 Qwen3-VL-Reranker-2B 对 (查询文本, 图片) 逐张实时评分（cross-encoder），
  以异步长任务执行并由 SSE 推送进度；完成后瀑布流按相似度降序重排，卡片前缀 `S`
  显示相似度（经 sigmoid 映射到 [0, 1]）。
- 查询框的「模式」可选 **语义描述** 或 **标签**：
  - **语义描述**：自由文本查询，交给 Qwen3-VL-Reranker-2B 按图文相似度排序，
    卡片前缀 `S`。
  - **标签**：逗号分隔的标签查询，交给标签评分器按 WD14 标签概率排序：单标签取该标签
    概率，多标签取各概率最小值（所有标签同时存在的置信度）；输入时按 WD14 标签表前缀
    补全（通用 / 角色 / 分级），下划线与空格等价，卡片前缀 `T`。只读取评分页已建立的
    推理缓存（`.wd14_meta`），不重新推理；缺缓存的图片不参与排序、排在末尾，并提示先到
    评分页建立缓存。
- 选中「搜索」后工具栏出现 **搜索** 按钮，打开搜索排序对话框（参考标签检查页）。
  语义模式提供最近搜索下拉；两种模式共用进度条与任务反馈。
- 语义模式每个数据集缓存最近 20 次排序结果：同一查询（含相同目录范围）再次执行时命中缓存，
  任务立即完成，无需重复调用模型；命中会提升该查询的保留优先级，避免被后续查询挤出。
  缓存排序之后新增的图片会重新调用模型评分，按相似度并入结果并回写缓存，
  保证返回结果覆盖当前全部候选。

## 远程模式（Gelbooru / Danbooru / e621 / Bilibili）

1. 「来源」选图站，输入标签，设置条件与页码后 **搜索**。
2. 左键触发 **下载** 并写入当前工作子目录；完成后状态为 **已保存**。
3. 顶栏 **已收录**（工作目录磁盘张数）· **已加载**（当前搜索结果）。点选即写入，无「已选择」。
4. 「条件」角标统计已生效项（评级、分数/宽高/ID、用户、附加元标签；日期适用于 Danbooru 与 e621）；悬停可看摘要。
5. 对已保存条目可 **移除**（从工作目录删去对应文件）；移除后「已收录」会刷新。
6. 工具栏页码显示当前可见卡片所属的搜索结果页；回车跳到指定页并回到列表顶部。
7. 向下滚到底部自动加载下一页；向上滚到顶部自动加载上一页，前插后保持当前阅读位置。
8. 切换来源或刷新页面时，恢复该来源上次离开的页码，并从该页开始加载。
9. 更改列数后会尽量回到原先浏览的页位。

远程产物（每个帖子）：图像、旁路 `.txt`、以及对应的元数据目录。

### Bilibili 模式

1. 「来源」选 **Bilibili**，输入 **UID**（必填）后搜索；可选按类型（图片/视频/转发）、关键词与发布时间区间筛选。类型默认只勾选 **图片**（视频/转发默认禁用），可在「条件」中开启。
2. 一条图文动态的多张原图会展开为多张独立卡片；转发动态取原文配图并在卡片标注「转发」，视频动态用封面。
3. 卡片预览在右侧以自然语言段落展示动态正文（而非标签芯片）。
4. 文件名形如 `bi{动态ID}_{序号}.png`，旁路 `.txt` 写入动态正文；元数据存于 `.bilibili_meta`。
5. 首次搜索会拉取该用户全部动态并缓存，之后分页读取缓存；换筛选条件会重新拉取。

## 新增来源

来源差异前后端均已收敛为注册表，新增来源只需在固定位置补一项：

后端（`services/online_sources/`）：
1. 为来源建独立子包（如 `danbooru/`、`gelbooru/`、`pixiv/`、`x/`），`__init__.py` 导出 `XxxSource`；有独立网络/客户端逻辑时拆 `client.py`（底层请求）与 `source.py`（`SourceClient` 适配器）。
2. 若用 gallery-dl 驱动（X / pixiv 等），`source.py` 继承 `framework/gallerydl.py` 的 `GalleryDLSource`，并实现 `_search_key` / `_search_url` / `_detail_url` / `_split_pid` / `_post_from_item` / `_caption_from_item` / `_auth_overrides` 等钩子；`search` / `download` / `fetch_meta` 均由基类提供。
3. 否则继承 `SourceClient`，自行实现 `search` / `download` / `fetch_meta`；查询串特殊时覆盖 `parse_query`。
4. `services/online_sources/__init__.py` 中 `register_source(XXXSource())`。
5. 若图床需防盗链代理，在 `SourceClient` 子类声明 `image_hosts` / `image_referer`（必要时覆盖 `image_timeout_for`）；`routes/online_sources.py` 的统一 `/online-sources/{source}-image` 端点会自动适配。

前端（`frontend/src/lib/api.ts` + `frontend/src/pages/filter/`）：
1. `SOURCES` 注册表加一项：`label` / `fields`（text / select / button）/ `requireTags` / `noJump` / `fixedAspect` / `hint`。
2. `thumbUrl` / `sampleUrl` / `pageUrl` 增加对应来源分支。
3. 搜索、分页、下载、预览由 `useFilterPage` 统一处理，无需改动业务主干。

## 代理

图片代理统一走 `/online-sources/{source}-image`：各来源声明图床白名单与 Referer（Gelbooru 另加图床 cookie），Danbooru 直链。搜索与图片出口使用 `HTTP_PROXY` / `HTTPS_PROXY`。

## 批量下载

工具栏 **批量下载**：服务端按当前搜索条件向后翻页下载，跳过已保存，直到达到指定张数。可设连接数（1–8）与限速（次/秒，0=不限）；运行中可改。进度在顶栏与对话框；**刷新页面会自动重连**进行中的任务。点「停止」可取消。Gelbooru 遇 HTTP 429 自动退避重试。
